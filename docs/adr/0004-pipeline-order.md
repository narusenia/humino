# ADR-0004: 処理の順番

- 状態: 採用
- 日付: 2026-11-18

## 背景

各処理は前の処理の結果を受け取るので、順番で結果が変わる。SDK のデザインガイドも、処理順に UI を並べることを勧めている。

## 決定

Groove → Humanize（タイミング、ベロシティ、長さ）→ Strum → 疑似ペダル → Connect（v2）の順に処理する。ダイアログのタブも同じ順に左から並べる。1 回の適用は `withinTransaction` で 1 つの取り消し単位にする。

## 結果

- 狙ったノリ（Groove）に人の揺れが乗り、その後で和音を崩す、という演奏の実感に近い順になる
- Connect は Strum のあとなので、追加したノートは Strum されない
